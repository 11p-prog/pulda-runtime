# Daily 업무 파악

## 언제 쓰는가

사용자가 `daily/` 폴더의 월별 메모(예: `2026.08.01.docx`)를 기반으로 자신의
업무 현황을 파악해달라고 요청할 때 사용한다. 이 파일은 하루치 할일을 이어서
누적 작성하며, 완료된 항목은 취소선으로 표시하는 것이 사용자의 기존 관례다.

`daily/`는 개인 업무 메모이며 `.gitignore`로 Git 커밋이 막혀 있다 — 이 스킬의
결과물도 daily/ 밖으로 전송하거나 외부 서비스에 올리지 않는다.

## 절차

1. **이번 달 파일 찾기**
   `daily/*.docx` 중 파일명(`YYYY.MM.DD.docx`)의 연·월이 오늘 날짜와 같은 파일을
   고른다. 없으면 `daily/` 안에서 가장 최근에 수정된 `.docx`를 대신 쓰고, 어떤
   파일을 사용했는지 결과 맨 위에 한 줄로 밝힌다. 새 달이 시작돼 아직 파일이
   없으면 그 사실을 알리고 멈춘다 (파일을 대신 만들지 않는다).

2. **구조화된 데이터 추출**
   ```
   python .claude/skills/daily-work-check/scripts/parse_daily.py <파일경로>
   ```
   를 실행해 JSON을 얻는다. 표준 라이브러리만 쓰는 읽기 전용 스크립트로,
   원본 파일을 수정하지 않는다. 출력 구조:
   - `top_block`: 첫 날짜 헤더 이전의 줄들 (보통 이번 달 반복업무 메모)
   - `days[]`: 날짜별 `{date, weekday, items: [{text, done}]}`
     (`done=true` = 취소선 처리된 완료 항목)

3. **JSON을 보고 직접 판단해서 정리한다** (하드코딩된 규칙이 아니라 내용을
   읽고 판단할 것)
   - **오늘 할 일**: 오늘 날짜 항목 중 `done=false`인 것.
   - **밀린 일 / 놓친 일**: 오늘 이전 날짜의 `done=false` 항목 중, 이후 날짜에
     같은 항목이 다시 적혀 있지 않은(=아직 처리 안 된) 것만 밀린 것으로 표시한다.
     반복 기록처럼 매일 다시 적히는 항목은 밀린 것으로 취급하지 않는다.
   - **반복업무 vs 중요업무 구분**: `top_block`의 반복업무 목록과 최근 항목을
     대조해 반복업무는 "반복"으로, 마감·외부연락·금액 등이 드러나는 굵직한
     항목은 "중요"로 표시한다.
   - **긴급도**: 항목 텍스트 속 날짜/기한 표현(예: "8/15까지", ">8/15")을 오늘
     날짜와 비교해 매긴다.
   - **다가오는 중요 일정**: 오늘 이후 날짜에 이미 적힌 항목, 또는 항목 텍스트
     속 미래 날짜 언급을 모은다.
   - **최근 현황 요약**: 최근 5~7일 항목을 자연어로 3~5줄 요약한다.

4. **출력**
   다음 다섯 항목을 한국어로, 읽기 쉬운 목록 형태로 채팅에 출력한다.
   1) 오늘 할 일  2) 밀린 일  3) 반복/중요 구분  4) 다가오는 일정
   5) 최근 현황 요약
   파일로 저장하지 않는다 — 저장은 사용자가 요청할 때만, `daily/` 안에.

## 주의

- `daily/` 내용은 개인 민감정보(가족·건강·재무 등)를 포함할 수 있다. 요약을
  Git에 커밋하거나 daily/ 밖의 파일·외부 서비스로 내보내지 않는다.
- 원본 `.docx`는 읽기만 하고 수정하지 않는다.
- JSON에 없는 내용을 추정해서 지어내지 않는다.
